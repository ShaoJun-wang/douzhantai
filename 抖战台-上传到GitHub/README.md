## 一、作品简介
「抖战台」是一个面向抖音电商从业者的**多智能体协同作战台**。它把选品、直播、投流素材、财务核算四个高频环节，封装成 4 个专职 AI Agent，并配一个**总指挥（Orchestrator）**：你只说一个作战目标，总指挥自动把它拆解、委派给 4 个 Agent **串联协同**完成，最后汇总成一份完整作战方案。

这正好命中 Qoder 赛道命门——**多智能体协同 + 记忆 + 工具链连接 + 长时委派**；实时生成后端挂阿里云百炼 DashScope，天然契合百炼赛道。

## 二、四大作战模块（专职智能体）
| 模块 | 作用 | 输入示例 |
|------|------|----------|
| 🔍 选品拆解 | 七步拆解法：痛点/人群/卖点/场景/价格带/竞品/钩子金句 | "便携式迷你榨汁杯，客单价 39-79" |
| 🎬 直播场景 | 生成 9:16 直播间方案：色彩/道具/机位/话术节奏/灯光 | "便携榨汁杯，明亮厨房风，主推 69" |
| 🎞️ 千川素材 | 产出 3 条千川短视频脚本（钩子-痛点-演示-见证-促单） | "卖点=可拆洗/USB充电，目标=点击率" |
| 📊 财务核算 | 输入流水自动算毛利/净利/ROI/盈亏预警（**强制调用计算器工具实时算**） | "GMV 12万，退款 1.2万，投流 3万…" |

## 三、⚔️ 一键作战（总指挥编排 · 核心能力）
在「⚔️ 一键作战」页写下一个目标，例如：
> 推一款便携式迷你榨汁杯，客单价 39-99，目标一二线年轻女性，想快速起量

总指挥按固定作战链路**长时委派** 4 个 Agent 顺序执行：
```
选品拆解 → 直播场景 → 千川素材 → 财务核算
```
**后一个 Agent 必须继承前一个的输出继续**（选品的钩子 → 直播的场景 → 千川的脚本 → 财务的核算对齐），形成一条连贯的作战方案，而不是 4 个孤立回答。最终在「总攻作战方案」卡片里看到 4 步结果 + 总攻建议。

## 四、真·Agent 内核（对应 Qoder 技术难度）
- **多智能体协同**：4 个专职 Agent 由总指挥编排串联，上下文逐环传递。
- **工具调用 tool-use（5 个）**：
  - `calculator` —— 财务 Agent 强制调用，实时计算毛利率/ROI/净利（不是口算）；
  - `feishu_fetch` —— 选品/千川 Agent 可调用，读取飞书多维表格竞品参考数据（演示用示例数据，证明工具链可读外部表格）；
  - `extract_table` —— 纯前端解析用户粘贴的流水/表格文本 → 结构化 JSON，供财务核算；
  - `trend_fetch` —— **真实 HTTP 工具**：经 `proxy.js` 的 `/api/trend` 实时拉取公开热榜（已验证返回真实微博热搜），命中 Qoder「工具链连接」命门；
  - `feishu_real` —— 真实飞书多维表格读取（`/api/feishu`，服务端配置 `FEISHU_APP_ID`/`FEISHU_APP_SECRET`/`FEISHU_APP_TOKEN` 即激活，未配置自动降级示例）。
  - 模型在回复中插入 `<<tool:name|参数>>`，运行时执行并把结果回传，模型据此产出最终结论（工具调用循环，最多 3 轮）。
- **知识引擎（记忆升级）**：每次作战后系统从结论中提炼洞察，沉淀到「全局知识库」，跨 Agent、跨会话复用；在专职智能体视图可看到「💡 全局知识库」面板，第二次同品类作战自动引用历史洞察——命中 Qoder「记忆与知识引擎」命门。
- **跨模块记忆**：每个 Agent 有独立记忆，对话历史经 localStorage 持久化，跨轮可继承；总指挥的作战上下文也逐环传递。
- **长时委派**：一个目标自动跑完整条链路并汇总，无需人工逐步串联。

## 八、本地代理模式（解决浏览器跨域 + Key 安全）
百炼接口在部分浏览器直接调用可能受 CORS 限制。附带的本地代理把前端请求转发到百炼，Key 放在服务端环境变量：
```bash
# 项目目录运行（需 Node）
set DASHSCOPE_API_KEY=sk-xxxx   # Windows
node proxy.js                    # 启动后访问 http://localhost:3000
```
如需激活真实飞书读取（`feishu_real` 工具），在同目录建 `.env` 并填三项（参考 `.env.example`）：
```bash
FEISHU_APP_ID=cli_xxxx
FEISHU_APP_SECRET=xxxx
FEISHU_APP_TOKEN=bascnxxxx   # 多维表格 URL 中的 app_token
```
不填则 `feishu_real` 自动降级为示例，演示模式零依赖可用。

如需进一步加固（**强烈建议公网部署时**），在 `.env` 增设 `PROXY_ACCESS_TOKEN`，并在前端设置面板「代理访问令牌」填同样的值：
```bash
PROXY_ACCESS_TOKEN=your-strong-random-token
```
设置后，未带正确 `Authorization: Bearer` 的请求访问 `/api/feishu` 会被拒绝（401），即使服务暴露在外网也不会被白嫖读飞书。

代理额外提供以下接口：
- `GET /api/health` —— 探测部署可达性（返回 `{ok:true, key:bool}`）；
- `POST /api/trend` —— 实时趋势工具链（真实 HTTP 拉取公开热榜，已验证返回真实微博热搜）；
- `POST /api/feishu` —— 真实飞书读取（需服务端 `FEISHU_APP_ID`/`FEISHU_APP_SECRET`/`FEISHU_APP_TOKEN`，三项齐全即激活真实多维表格读取，未配置自动降级）。

## 九、技术架构
- 纯前端单页应用（HTML + CSS + 原生 JS），零构建、零依赖，打开即跑；
- **真·Agent 内核**：`agents.js` 定义 4 个 Agent + 工具（TOOLS）+ 总指挥编排（PIPELINE / aggregateCampaign）；
- 运行时 `app.js`：工具调用循环、跨模块记忆（localStorage）、一键作战 UI；
- 模型调用走百炼 DashScope 兼容 OpenAI 协议；可静态托管，公网可访问。

## 十、安全说明（渗透测试视角）
- **密钥不泄露**：Key 仅存浏览器 localStorage 或服务端环境变量，不进代码、不上传；生产建议走 proxy.js。
- **输入校验 / 防 XSS**：所有模型输出经 `renderMD` 先 HTML 转义再渲染；工具算术用 `safeEvalMath` 白名单校验，杜绝代码注入。
- **演示降级**：调用失败自动回退演示结果，避免空页面/崩溃。
- **无敏感落库**：作品不收集、不存储任何用户业务数据。
- **无外部跟踪**：页面不含第三方统计/跟踪脚本。
